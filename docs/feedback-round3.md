## 二、第 5 条：解析器目前确切的薄弱点

1. `_priorityPattern` 要求 `A` 前后是空白或行首尾 → `A级打卡`（后面直接跟汉字）匹配不到。
2. `_durationPattern` 里 `分` 会先于 `分钟` 命中，`1个半小时` 不支持，`90分钟` 可以。
3. `_timePattern` 不认区间（`8:30-9:00`）、不认「上午/中午」；只有全局 `晚|下午|夜` 触发 +12h。
4. `10点半` 的「半」和 `10:30 半` 会重复命中。
5. 标题里会残留数字碎片（如 `45分` 吃掉后剩空格，虽已折叠但 `45` 若被日期规则咬掉会丢内容）。
6. 英文/数字混排时 `h` 与 `min` 的 `caseSensitive: false` 有效，但 `H` 在标题里（如 `H5 页面`）会被当小时。

**建议**：解析结果实时高亮（已识别部分变灰、未识别保留），用户一眼看出哪段没吃进去；再给我 3–5 句你觉得不对的原句，我按真实 case 修，比盲改准。

## 三、他没想到、但会痛的（建议一并做）

| 建议 | 为什么 |
|---|---|
| 分列后加宽命中容差（左右各 4px）+ 点空白列选中该时段最长的块 | 分列变窄后手指点不中，会误以为卡住 |
| 锁定态允许长按只读菜单（编辑置灰、复制/搜索可用） | 现在锁定时长按无反应，容易被当成 bug |
| 边缘自动滚动改成「越靠边越快」（6px/帧固定太慢） | 拖长距离要等很久 |
| 缩放很小时刻度自动降级为每 2 小时 | 1 小时刻度在小缩放下会糊成一团 |
| 置顶投影卡片点击 → 滚到它在原泳道的位置 | 现在只选中，用户还得自己找 |
| 桌面 Shift+滚轮切天 / Ctrl+滚轮缩放 | 桌面用户最自然的两个手势 |
| JSON 导出/导入（复用同步快照格式） | 开源必备，也是唯一的手动备份手段 |
| 撤销队列支持连续两次（删除 A 再删 B，A 的撤销不该丢） | 现在 SnackBar 会互相顶掉 |

## 四、需要你确认的 5 个问题

1. **清空范围**：只清「今天未完成的」，还是连已完成记录一起清？（我建议前者）
2. **一句话解析**：能给 3–5 句「看起来不对」的原句吗？
3. **圆盘 vs 滚动数字**：手机上你更想要哪种？（我建议滚动数字，更稳，也不加 Cupertino 依赖）
4. **UI 自定义范围**：字号/密度/主题色这三样够吗，还是你想要调泳道宽度、圆角这种？
5. **上下箭头**：上把手是不是应该保持「结束时间不动」（即同时改开始+时长）？还是只改开始？
